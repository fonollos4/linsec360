# LinSec360

LinSec360 is a Linux security orchestration platform built around a FastAPI
backend, React UI, PostgreSQL, Redis/RQ, Ansible automation, and the Wazuh
control plane. The complete supported deployment is defined by
[`docker-compose.v2.yml`](docker-compose.v2.yml).

Additional project documentation is indexed in [docs/INDEX.md](docs/INDEX.md).

## Start the V2 FastAPI + React + Wazuh stack

Run every command below from the repository root.

### 1. Create the deployment environment

From the repository root:

```bash
cp .env.example .env
chmod 600 .env
python3 config/scripts/init-wazuh-env.py
```

This initializes all missing LinSec/Wazuh secrets listed by
`init-wazuh-env.py`, including random passwords and matching Wazuh bcrypt
hashes. Review every value in `.env` before production deployment.

Required application values without automatic defaults are:

- `LINSEC_SECRET_KEY`
- `LINSEC_BOOTSTRAP_ADMIN_PASSWORD`
- `POSTGRES_PASSWORD`
- `WAZUH_ADMIN_PASSWORD`
- `WAZUH_DASHBOARD_PASSWORD`
- `WAZUH_API_PASSWORD`

The last three are generated by the initialization command above.

The first copy of `.env.example` also contains the Uyuni placeholders. Uyuni
is optional and can be left empty when starting the standard stack.

To enable Uyuni, generate its application and database secrets and keep the
same administrator password in both variables:

```bash
UYUNI_ADMIN_PASSWORD=$(openssl rand -hex 32)
sed -i \
  -e "s/^LINSEC_UYUNI_PASSWORD=.*/LINSEC_UYUNI_PASSWORD='$UYUNI_ADMIN_PASSWORD'/" \
  -e "s/^UYUNI_ADMIN_PASSWORD=.*/UYUNI_ADMIN_PASSWORD='$UYUNI_ADMIN_PASSWORD'/" \
  .env
for key in UYUNI_POSTGRES_PASSWORD UYUNI_DB_PASSWORD UYUNI_REPORT_DB_PASSWORD; do
  value=$(openssl rand -hex 32)
  sed -i "s/^${key}=.*/${key}='$value'/" .env
done
chmod 600 .env
```

### 2. Prepare host and Wazuh configuration

Increase the Linux virtual-memory limit for the Wazuh Indexer:

```bash
sudo sysctl -w vm.max_map_count=262144
```

Render Wazuh private configuration:

```bash
python3 config/scripts/render-wazuh-config.py
```

Generate TLS certificates only when
`config/wazuh/indexer_ssl_certs/root-ca.pem` does not exist:

```bash
test -f config/wazuh/indexer_ssl_certs/root-ca.pem || \
  docker compose -p linsec360-certs -f generate-indexer-certs.yml run --rm generator
```

Do not rerun the certificate generator after certificates already exist.

### 3. Start and verify the stack

```bash
docker compose -f docker-compose.v2.yml up --build -d
docker compose -f docker-compose.v2.yml ps
```

The V2 stack exposes the React UI on `LINSEC_WEB_PORT` (default `80`), the API
on `LINSEC_API_PORT` (default `8080`), Wazuh Dashboard on
`WAZUH_DASHBOARD_PORT` (default `443`), Wazuh Manager API on
`WAZUH_API_PORT` (default `55000`), and the Indexer on `WAZUH_INDEXER_PORT`
(default `9200`). API and worker containers already include `ansible-core 2.18`;
verify with:

```bash
docker compose -f docker-compose.v2.yml exec api ansible-playbook --version
docker compose -f docker-compose.v2.yml exec worker ansible-playbook --version
```

To include Uyuni in the stack, fill all `UYUNI_*_PASSWORD` values and the
`UYUNI_FQDN` setting in `.env`, then start the services with the Uyuni profile:

```bash
docker compose -f docker-compose.v2.yml --profile uyuni up --build -d
docker compose -f docker-compose.v2.yml --profile uyuni ps
```

Uyuni exposes HTTP on `UYUNI_HTTP_PORT` (default `8081`) and HTTPS on
`UYUNI_HTTPS_PORT` (default `8443`). LinSec360 connects to the XML-RPC endpoint
internally at `http://uyuni/rpc/api`; use the **Paramètres > Intégrations**
test before synchronizing patch data from **Correctifs**.

Uyuni is initialized once and may take several minutes on its first start. Wait
for both containers to become healthy:

```bash
docker compose -f docker-compose.v2.yml --profile uyuni ps uyuni-db uyuni
docker compose -f docker-compose.v2.yml --profile uyuni logs --tail=100 uyuni
```

Expected healthy URLs:

```bash
curl http://localhost:8080/health
curl http://localhost:8080/ready
curl http://localhost/
```

Open the LinSec360 UI at `http://localhost`, and Wazuh Dashboard at
`https://localhost`. Wazuh Dashboard uses the generated Wazuh admin credentials
from `.env`.

To start later without rebuilding, use:

```bash
docker compose -f docker-compose.v2.yml up -d --remove-orphans
```

To view startup errors:

```bash
docker compose -f docker-compose.v2.yml logs --tail=100
```

### Reset the LinSec360 web administration password

`LINSEC_BOOTSTRAP_ADMIN_PASSWORD` is used only when the database has no users.
Changing this value in `.env` does not update an existing `admin` account.
Changing it after database initialization therefore cannot change the password
used by the web login.

Reset the existing account directly from the running API container:

```bash
docker compose -f docker-compose.v2.yml exec api \
  python -m backend.cli reset-password --username admin
```

Enter a password of at least 12 characters at the secure prompt. The command
updates the Argon2 password hash stored in PostgreSQL and revokes every active
LinSec360 session for that user. Do not pass the password with `--password` in
shell scripts or terminal history.

After the reset, update the bootstrap value in `.env` so a database
reinitialization uses the same password:

```bash
LINSEC_BOOTSTRAP_ADMIN_USERNAME=admin
LINSEC_BOOTSTRAP_ADMIN_PASSWORD='<the-new-secret>'
```

Keep `.env` mode `0600`, do not commit the password, and restart the API if a
new bootstrap value must also be available to the running configuration:

```bash
chmod 600 .env
docker compose -f docker-compose.v2.yml up -d --force-recreate api
```

For a completely new database:

```bash
docker compose -f docker-compose.v2.yml stop api
docker volume rm linsec360_linsec_postgres
docker compose -f docker-compose.v2.yml up -d --build
```

The last procedure deletes all LinSec360 users, deployment history and
application database data. It is therefore suitable only for a disposable test
database.

In production, never delete the PostgreSQL volume. Use the CLI reset above,
restrict the operation to approved operators, revoke the old browser sessions,
store the new secret in a secret manager or approved environment configuration,
and verify HTTPS, proxy cookies and `LINSEC_COOKIE_SECURE` before reopening
access. The bootstrap password must remain a one-time initialization setting
and must not be treated as the password-management mechanism for an existing
database.

### Reset Wazuh test data and security users

This procedure is intended for disposable test environments. It removes the
indexer's persisted OpenSearch security state and alerts, then initializes the
Wazuh users from the current values and bcrypt hashes in `.env`.

Stop the stack and remove only the Wazuh Indexer data volume:

```bash
docker compose -f docker-compose.v2.yml down
docker volume rm linsec360_wazuh-indexer-data
python3 config/scripts/render-wazuh-config.py
docker compose -f docker-compose.v2.yml up -d --build
```

If a different Compose project name was used, determine the actual volume name
first:

```bash
docker volume ls --format '{{.Name}}' | grep 'wazuh-indexer-data'
docker compose -f docker-compose.v2.yml down
docker volume rm <linsec360_wazuh-indexer-data-from-the-command-above>
```

Then regenerate the configuration and start the stack again. Do not use
`docker compose down -v` unless every LinSec360 and Wazuh data volume is
intentionally disposable.

For production, do not remove the Wazuh Indexer volume. First create an
approved backup or snapshot and record the recovery procedure. Rotate or
synchronize the `Wazuh` security users through the Security configuration or the
Security API, preserve the existing index and volumes, verify every Wazuh
service with the new credentials, and only then update `.env`. A destructive
reset is appropriate in production only during an explicitly approved
environment rebuild and after a tested restoration plan is available.
