# LinSec360

LinSec360 is a Linux security orchestration platform built around a FastAPI
backend, React UI, PostgreSQL, Redis/RQ, Ansible automation, and the Wazuh
control plane. The complete supported deployment is defined by
[`docker-compose.v2.yml`](docker-compose.v2.yml).

Additional project documentation is indexed in [docs/INDEX.md](docs/INDEX.md).

## Current deployment model

- Uyuni/Salt is **no longer part of the stack**. It was removed from Compose,
  runtime configuration, deployment worker, and the UI. Legacy API/model fields
  may still exist for compatibility, but no Uyuni container or profile is
  started.
- All automation lives under [`taskengine/`](taskengine/): playbooks, roles,
  inventories, and `ansible.cfg`. Do not add root-level `playbooks/`, `roles/`,
  `inventories/`, or `ansible.cfg`.
- SSH host fingerprints are **not scanned, pinned, or compared**. An administrator
  must provision a service account (default `linsec-ansible`) on every target and
  install the matching public key before onboarding the host.
- The UI provides bulk host import, fleet filtering, grouped actions, an
  authenticated WebSocket terminal, and OpenSCAP/patching controls. See
  [docs/architecture/ui-enrichment.md](docs/architecture/ui-enrichment.md).

## Start the stack on this server

Run every command from the repository root.

### 1. Prerequisites

- Docker Engine with the Compose plugin
- Python 3 and `openssl`
- Permission to raise the Wazuh Indexer memory limit:

  ```bash
  sudo sysctl -w vm.max_map_count=262144
  ```

- Free host ports (defaults): `80` (UI HTTP redirect), `8444` (UI HTTPS),
  `8080` (API, bound to `127.0.0.1` only), `443` (Wazuh Dashboard), `9200`
  (Wazuh Indexer), `55000` (Wazuh Manager API), `1514`/`1515` (agent/enrollment),
  and `514/udp` (syslog). All ports can be overridden in `.env`.

### 2. Create the deployment environment

```bash
cp .env.example .env
chmod 600 .env
python3 config/scripts/init-wazuh-env.py
```

This initializes missing LinSec/Wazuh secrets, including random passwords and
matching Wazuh bcrypt hashes. Review every value in `.env` before use. Never
commit `.env`.

Required values:

- `LINSEC_SECRET_KEY` — generate with `openssl rand -hex 32`
- `LINSEC_CREDENTIAL_ENCRYPTION_KEY` — generate with
  `openssl rand -base64 32 | tr '+/' '-_'`; keep it stable and backed up
- `LINSEC_BOOTSTRAP_ADMIN_PASSWORD`
- `POSTGRES_PASSWORD`
- `WAZUH_ADMIN_PASSWORD`, `WAZUH_DASHBOARD_PASSWORD`, `WAZUH_API_PASSWORD`
  (generated by `init-wazuh-env.py`)

`LINSEC_BOOTSTRAP_ADMIN_PASSWORD` is used **only when the database has no
users**. Changing it later does not change an existing `admin` password; use the
reset procedure below instead.

This server runs in production mode with TLS enabled. Keep the following in
`.env`:

```dotenv
LINSEC_ENVIRONMENT=production
LINSEC_TLS_ENABLED=true
LINSEC_COOKIE_SECURE=true
LINSEC_WEB_PORT=80
LINSEC_HTTPS_PORT=8444
LINSEC_API_PORT=8080
```

For a local development stack without TLS, set `LINSEC_TLS_ENABLED=false` and
`LINSEC_COOKIE_SECURE=false`; production startup fails if TLS is enabled without
certificate files, or if production mode has TLS disabled.

### 3. Prepare TLS and Wazuh configuration

Generate the UI certificate only if it does not already exist:

```bash
test -f config/tls/fullchain.pem || \
  LINSEC_TLS_HOSTS="$(hostname -f),localhost,127.0.0.1,<SERVER_IP>" \
  ./config/scripts/generate-linsec-tls.sh
```

The script writes `config/tls/fullchain.pem` and `config/tls/privkey.pem` (mode
`0600`) and refuses to overwrite existing files. It is self-signed, so browsers
will show a warning; replace it with a trusted certificate for public use.

Render Wazuh private configuration:

```bash
python3 config/scripts/render-wazuh-config.py
```

Generate Wazuh Indexer certificates only when
`config/wazuh/indexer_ssl_certs/root-ca.pem` does not exist:

```bash
test -f config/wazuh/indexer_ssl_certs/root-ca.pem || \
  docker compose -p linsec360-certs -f generate-indexer-certs.yml run --rm generator
```

Do not rerun the certificate generator after certificates already exist.

### 4. Prepare the Ansible service-account key

The API and worker mount `LINSEC_SSH_KEY_DIR` (default `./.ssh`) read-only at
`/opt/linsec/.ssh`. Generate the default key without overwriting an existing
one:

```bash
./config/scripts/generate-ansible-key.sh
```

Ensure the host directory is owned by `LINSEC_UID`/`LINSEC_GID` so the containers
can read the mode-`0600` private key. Install the printed public key in the
service account's `~/.ssh/authorized_keys` on every managed host. Passphrase
protected keys are not supported.

`LINSEC_ANSIBLE_SSH_PRIVATE_KEY_PATH` must point to the **container** path
(default `/opt/linsec/.ssh/id_ed25519`). Recreate both `api` and `worker` after
changing it:

```bash
docker compose -f docker-compose.v2.yml up -d --force-recreate api worker
```

### 5. Start the stack

```bash
docker compose -f docker-compose.v2.yml up -d --build --remove-orphans
docker compose -f docker-compose.v2.yml ps
```

`--remove-orphans` also removes old Uyuni containers from a previous deployment.
For later starts without rebuilding:

```bash
docker compose -f docker-compose.v2.yml up -d --remove-orphans
```

Expected URLs:

```bash
curl -fsS http://127.0.0.1:8080/health
curl -fsSk https://127.0.0.1:8444/health
```

Open the UI at `https://localhost:8444` on this server (or `http://localhost`
when TLS is disabled). Wazuh Dashboard is at `https://localhost:443`. Log in with
`admin` and the password from the initial bootstrap or from the reset procedure
below.

Startup errors can be inspected with:

```bash
docker compose -f docker-compose.v2.yml logs --tail=100 api worker web
```

### 6. Verify Ansible automation

The API and worker images include `ansible-core 2.18`, `openssh-client`, and the
collections from `taskengine/requirements.yml`:

```bash
docker compose -f docker-compose.v2.yml exec api ansible-playbook --version
docker compose -f docker-compose.v2.yml exec api ansible-playbook \
  --syntax-check \
  -i /opt/linsec/taskengine/inventories/production/hosts.yml \
  /opt/linsec/taskengine/playbooks/site.yml
docker compose -f docker-compose.v2.yml exec api ansible-playbook \
  --syntax-check \
  -i /opt/linsec/taskengine/inventories/production/hosts.yml \
  /opt/linsec/taskengine/playbooks/verify.yml
```

Available playbooks include `site.yml` (baseline hardening), `verify.yml`,
`openscap-scan.yml`, `hardening.yml`, `patch-security.yml`,
`livepatch-check.yml`, `wazuh-agent.yml`, `connectivity.yml`, and
`site-legacy.yml` (the preserved pre-baseline playbook). Inventories generated
from the database are authoritative for deployments; the files under
`taskengine/inventories/` are examples for local/syntax runs only.

### 7. Wazuh manager address for agents

The Settings page resolves configured service hostnames to IP addresses from the
API container and summarizes the Web UI, API, database, Redis, and Wazuh
Manager/API/Indexer/Dashboard. For `wazuh-agent.yml`, LinSec derives the manager
address from `LINSEC_WAZUH_API_URL` when that hostname is not the Docker-only
`wazuh.manager` alias. In the default Docker setup, set
`LINSEC_WAZUH_MANAGER_ADDRESS` to the manager IP or DNS name reachable from
managed hosts; the page identifies internal Docker addresses so they are not
mistaken for a remote agent endpoint. Recreate API and worker after changing it.

## Host onboarding and terminal

- Add a host from the UI with name/alias, IPv4, environment, groups, SSH user,
  port, and an optional SSH key reference. **Tester la connexion** checks SSH via
  the service account and detects the distribution with Ansible.
- Bulk import accepts CSV with headers
  (`name,ip,environment,groups,ansible_user,ansible_port,ssh_key_reference`),
  JSON, or pasted `hostname,ip,ssh_user,group,environment` lines. Invalid and
  selected rows are previewed before import.
- The **Déployer après ajout** option queues the first allowlisted playbook
  (`site.yml` when available).
- The terminal button opens `WS /api/v1/hosts/{id}/terminal/ws`. Access requires
  an authenticated session or Bearer token with role `admin` or `operator`;
  openings and closures are written to the audit log. The nginx location in
  `web/snippets/linsec-locations.conf` handles the WebSocket upgrade.
- Long running deployments are tracked from `/deployments`, its SSE feed, and
  detailed logs. OpenSCAP remediation excludes SSH-cutting rules and does not
  open Wazuh ports `1514`/`1515`; before/after reports are written under
  `/var/log/linsec360/` on the target.

There is no fingerprint approval screen. Legacy fingerprint endpoints remain
importable for compatibility but are not used by the UI, connection tests, or
the deployment worker.

## Reset the LinSec360 web administration password

`LINSEC_BOOTSTRAP_ADMIN_PASSWORD` is used only when the database has no users.
Changing this value in `.env` does not update an existing `admin` account.

Reset the existing account directly from the running API container:

```bash
docker compose -f docker-compose.v2.yml exec api \
  python -m backend.cli reset-password --username admin
```

Enter a password of at least 12 characters at the secure prompt. The command
updates the Argon2 password hash stored in PostgreSQL and revokes every active
LinSec360 session for that user. Do not pass the password with `--password` in
shell scripts or terminal history.

After the reset, update the bootstrap value in `.env` so a database
reinitialization uses the same password:

```dotenv
LINSEC_BOOTSTRAP_ADMIN_USERNAME=admin
LINSEC_BOOTSTRAP_ADMIN_PASSWORD='<the-new-secret>'
```

Keep `.env` mode `0600`, do not commit the password, and restart the API if the
new bootstrap value must also be available to the running configuration:

```bash
chmod 600 .env
docker compose -f docker-compose.v2.yml up -d --force-recreate api
```

For a completely new database:

```bash
docker compose -f docker-compose.v2.yml stop api
docker volume rm linsec360_linsec_postgres
docker compose -f docker-compose.v2.yml up -d --build
```

This deletes all LinSec360 users, deployment history, and application data; use
it only for a disposable test database. In production, never delete the
PostgreSQL volume. Use the CLI reset above, restrict it to approved operators,
revoke old browser sessions, store the secret in an approved secret manager, and
verify HTTPS/proxy cookies before reopening access.

## Remove a previous deployment before a fresh install

Use this only when you intentionally want to erase the existing stack data. It
permanently deletes the LinSec360 PostgreSQL database, Redis state, Wazuh
indexes and configuration data, and application logs/artifacts stored in Compose
volumes. Back up anything that must be retained first.

Verify the project and services:

```bash
docker compose -f docker-compose.v2.yml ps --all
```

Stop and remove the containers, orphan containers, and all Compose-managed
volumes:

```bash
docker compose -f docker-compose.v2.yml down --volumes --remove-orphans
```

This does not delete `.env`, source files, bind-mounted configuration, or TLS
certificates. Keep those files for the reinstall and change/regenerate secrets
separately only when required. Do not run a global `docker system prune` or
manually remove unrelated Docker volumes.

Prepare the configuration again, then reinstall:

```bash
python3 config/scripts/render-wazuh-config.py
docker compose -f docker-compose.v2.yml up --build -d
docker compose -f docker-compose.v2.yml ps
```

Repeat the certificate-generation steps only if the certificates do not exist.

## Reset Wazuh test data and security users

This procedure is intended for disposable test environments. It removes the
indexer's persisted OpenSearch security state and alerts, then initializes the
Wazuh users from the current values and bcrypt hashes in `.env`.

```bash
docker compose -f docker-compose.v2.yml down
docker volume rm linsec360_wazuh-indexer-data
python3 config/scripts/render-wazuh-config.py
docker compose -f docker-compose.v2.yml up -d --build
```

If a different Compose project name was used, determine the actual volume name
first:

```bash
docker volume ls --format '{{.Name}}' | grep 'wazuh-indexer-data'
docker compose -f docker-compose.v2.yml down
docker volume rm <linsec360_wazuh-indexer-data-from-the-command-above>
```

Do not use `docker compose down -v` unless every LinSec360 and Wazuh data volume
is intentionally disposable. In production, take an approved backup or snapshot
first and rotate/synchronize Wazuh security users through the Security API
without removing the index volume.
